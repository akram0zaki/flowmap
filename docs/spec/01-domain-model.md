# 01 — Domain Model

Normative definitions for every persisted entity. All types live in `@flowmap/domain`, are mirrored
by Zod schemas in the same package, and are validated at every trust boundary
(file, provider, IPC, import).

## 1. Identity, versioning, and common envelope

### 1.1 IDs

```ts
type EntityId = string; // ULID, 26 chars, Crockford base32, lexicographically sortable
type WorkspaceId = EntityId;
type ActorId = string; // local profile id, or `entra:<oid>` once linked
```

- IDs are **ULIDs**, generated by an injected `IdGenerator`. Domain code never calls a global
  random or clock source.
- IDs are immutable and stable across export/import and provider migration.
- Quarter IDs are structured, not ULIDs (see §2).

### 1.2 Common envelope

Every synchronised entity carries:

```ts
type EntityEnvelope = {
  id: EntityId;
  workspaceId: WorkspaceId;
  schemaVersion: number; // workspace schema version this row was written under
  entityVersion: number; // monotonic per entity; incremented by every accepted mutation
  createdAt: IsoDateTime; // UTC instant
  createdBy: ActorId;
  updatedAt: IsoDateTime;
  updatedBy: ActorId;
  archivedAt?: IsoDateTime; // presence == archived (soft removal)
  archivedBy?: ActorId;
  deletedAt?: IsoDateTime; // presence == tombstone (hard delete, Admin only)
  remoteVersion?: string; // provider-supplied concurrency token (ETag). Local cache only.
};
```

Rules:

- **Archive** is the normal user-facing removal. Archived entities keep all links and history, are
  hidden from default views, are excluded from capacity and rules, and can be restored.
- **Delete** is Admin-only, produces a tombstone (`deletedAt` set, payload fields cleared except
  `id`/`workspaceId`), and synchronises as a tombstone so peers converge.
- `entityVersion` is the basis of optimistic concurrency and undo. It increments on every accepted
  command, including archive and restore.

### 1.3 Primitive value types

```ts
type IsoDate = string; // 'YYYY-MM-DD', interpreted in the workspace timezone
type IsoDateTime = string; // RFC 3339 UTC, e.g. '2026-08-15T09:00:00Z'
type Confidence = 'LOW' | 'MEDIUM' | 'HIGH';
type RelativeSize = 'XS' | 'S' | 'M' | 'L' | 'XL';
type CapacityUnits = number; // non-negative integer

type OwnerRef = { kind: 'PERSON'; personId: EntityId } | { kind: 'TEAM'; teamId: EntityId };

type EntityRef =
  | { kind: 'COMMITMENT'; id: EntityId }
  | { kind: 'DEPENDENCY'; id: EntityId }
  | { kind: 'DECISION'; id: EntityId }
  | { kind: 'MILESTONE'; id: EntityId }
  | { kind: 'TEAM_QUARTER'; id: EntityId }
  | { kind: 'CAPACITY_FOOTPRINT'; id: EntityId }
  | { kind: 'PRODUCT_SERVICE'; id: EntityId }
  | { kind: 'PRODUCT_QUARTER'; productServiceId: EntityId; quarterId: QuarterId }
  | { kind: 'TEAM'; id: EntityId }
  | { kind: 'SCENARIO'; id: EntityId }
  | { kind: 'WORKSPACE'; id: WorkspaceId };
```

`CapacityUnits` MUST be a non-negative integer. All capacity arithmetic is integer arithmetic; no
floating point is permitted in capacity totals. Derived ratios (utilisation) are floats and are only
ever presented rounded to whole percent.

## 2. Quarters and time

### 2.1 Quarter identity

Planning always uses **calendar quarters**. Fiscal and custom calendars are out of scope.

```ts
type QuarterId = `${number}-Q${1 | 2 | 3 | 4}`; // e.g. '2026-Q3'

type Quarter = {
  id: QuarterId;
  year: number;
  quarter: 1 | 2 | 3 | 4;
  ordinal: number; // year * 4 + (quarter - 1). Sole basis for ordering and arithmetic.
  startDate: IsoDate; // first day, workspace timezone
  endDate: IsoDate; // last day, workspace timezone
};
```

| Quarter | Months             |
| ------- | ------------------ |
| Q1      | January – March    |
| Q2      | April – June       |
| Q3      | July – September   |
| Q4      | October – December |

Quarters are **computed, not stored**. `TeamQuarter` rows reference a `QuarterId` string. Ordering,
"next quarter", and horizon windows are all `ordinal` arithmetic.

### 2.2 Timezone and the clock

- A workspace has exactly one IANA timezone, chosen at creation, defaulting to the creating user's
  local zone. It determines calendar-day boundaries for every date field and every rule evaluation.
- All rule evaluation and date comparison goes through an injected `Clock`:

```ts
interface Clock {
  now(): IsoDateTime; // UTC instant
  today(tz: string): IsoDate; // calendar date in the workspace timezone
}
```

- Tests inject a fixed clock. **No domain or rules code may call `Date.now()` or `new Date()`.**
  This is enforced by an ESLint rule (`no-restricted-globals`) in the `domain`, `rules`, and
  `visual-model` packages.

### 2.3 Horizon

The default planning horizon is **6 quarters** (18 months) starting at the workspace's current
quarter minus one. Horizon presets: `NOW` (current ±1), `QBR` (current + next 2), `HORIZON`
(current −1 … current +5). The horizon is a view concern, never a data filter for capacity totals.

## 3. Workspace

```ts
type Workspace = EntityEnvelope & {
  name: string; // 1..80 chars
  timezone: string; // IANA zone, e.g. 'Europe/Amsterdam'
  currentQuarterId: QuarterId; // advanced only by CloseQuarter
  isSample: boolean; // sample workspaces are resettable and visually marked
  settings: WorkspaceSettings;
  revision: number; // baseline revision; increments on every applied baseline command
};

type WorkspaceSettings = {
  capacity: {
    defaultTeamQuarterCapacity: CapacityUnits; // default 100
    sizeMapping: Record<'XS' | 'S' | 'M' | 'L', CapacityUnits>; // default { XS:5, S:10, M:20, L:35 }
    xlRequiresExplicitUnits: true; // fixed; XL has no mapping
    defaultReserves: Array<{ type: ReserveType; amount: CapacityUnits; label: string }>;
    // default: [{ BAU_SUPPORT, 15, 'BAU & support' }, { REFINEMENT, 5, 'Refinement' }]
  };
  rules: RuleSettings; // see 04-rules-radar.md §7
  changeLoad: ChangeLoadSettings; // see 04-rules-radar.md §5
  guardrails: GuardrailSettings; // see 03-commands-permissions.md §6
  valueDrivers: string[]; // default list, workspace-editable
  notes: { maxLength: 2000 }; // fixed
  milestones: { maxPerCommitment: 6 }; // fixed
  notifications: NotificationSettings; // see 10-desktop-security.md §5
  presentation: { defaultLens: LensId; reducedMotion: 'SYSTEM' | 'ON' | 'OFF' };
};
```

`revision` is the baseline concurrency counter used by scenario rebase (see [05](05-scenarios-qbr.md)).
It increments once per successfully applied **baseline** command batch, never for scenario commands.

## 4. Team and capacity containers

```ts
type Team = EntityEnvelope & {
  name: string; // 1..60, unique (case-insensitive) among non-archived teams
  description?: string; // <= 500
  defaultQuarterCapacity: CapacityUnits; // seed for new TeamQuarters; default from workspace
  displayOrder: number; // integer; default alphabetical seed, Planner-reorderable
  active: boolean;
};

type TeamQuarter = EntityEnvelope & {
  teamId: EntityId;
  quarterId: QuarterId;
  capacityBaseline: CapacityUnits; // seeded from team.defaultQuarterCapacity
  capacityAdjustment: number; // signed integer; vacancies, ramp-up, leave
  adjustmentNote?: string; // <= 280; why the adjustment exists
  reserves: CapacityReserve[];
  closedAt?: IsoDateTime; // set by CloseQuarter; closed team-quarters are immutable
  overflowAccepted?: { acceptedBy: ActorId; acceptedAt: IsoDateTime; reason?: string };
};

type ReserveType = 'BAU_SUPPORT' | 'LCM' | 'OVERHEAD' | 'REFINEMENT' | 'HOLD' | 'OTHER';

type CapacityReserve = {
  id: EntityId;
  type: ReserveType;
  label: string; // <= 60
  amount: CapacityUnits;
  linkedIdeaIds?: EntityId[]; // REFINEMENT only; qualitative, allocates no units
  systemManaged?: boolean; // HOLD reserves are system-managed
};
```

Invariants:

- `(teamId, quarterId)` is unique among non-deleted `TeamQuarter` rows. A `TeamQuarter` is created
  lazily on first need (`EnsureTeamQuarter`) and is never implicit in calculations.
- `capacityBaseline + capacityAdjustment >= 0`.
- `Σ reserves.amount <= capacityBaseline + capacityAdjustment`. A command that would break this is
  rejected with `RESERVES_EXCEED_CAPACITY`.
- `linkedIdeaIds` is only permitted on `REFINEMENT` reserves and only references commitments whose
  lifecycle is `IDEA`. The link is **qualitative**: it explains what the bucket supports and
  contributes zero units to any individual Idea.
- `HOLD` reserves are created and removed only by `HoldCommitment` / `ResumeCommitment` with
  `preserveCapacity: true`, carry `systemManaged: true`, and cannot be edited directly.
- A closed `TeamQuarter` rejects every mutation except `ReopenQuarter` (Admin).

## 5. Commitment

```ts
type Lifecycle = 'IDEA' | 'COMMITTED' | 'IN_DELIVERY' | 'ON_HOLD' | 'DONE' | 'DROPPED';

type CommitmentClass = 'MANDATORY' | 'STRATEGIC' | 'OPERATIONAL' | 'DISCRETIONARY';
type Importance = 'HIGH' | 'MEDIUM' | 'LOW';

type Commitment = EntityEnvelope & {
  name: string; // 1..140, required at creation
  lifecycle: Lifecycle;
  priorActiveLifecycle?: 'COMMITTED' | 'IN_DELIVERY'; // set only while ON_HOLD
  class: CommitmentClass; // default 'DISCRETIONARY'
  importance: Importance; // default 'MEDIUM'

  primaryTeamId?: EntityId; // required to pass Commit Gate
  ownerRef?: OwnerRef;

  targetQuarterId?: QuarterId;
  targetDate?: IsoDate; // optional precision; setting it derives targetQuarterId

  sizeConfidence?: Confidence;
  timingConfidence?: Confidence;
  scopeConfidence?: Confidence;

  outcome?: string; // <= 280
  valueDrivers: string[]; // subset of workspace value drivers

  attentionDate?: IsoDate;
  latestSafeStart?: IsoDate;
  nextAction?: string; // <= 280
  nextActionOwnerRef?: OwnerRef;
  nextActionDueDate?: IsoDate;

  managementNote?: string; // <= 2000

  recurrence?: { pattern: 'QUARTERLY' | 'ANNUAL' | 'CUSTOM'; intervalQuarters?: number };
  renewedFromCommitmentId?: EntityId; // set when created from a DONE/DROPPED predecessor

  committedAt?: IsoDateTime; // set by PassCommitGate
  committedBy?: ActorId;
  lastMeaningfulUpdateAt?: IsoDateTime; // see 03 §4 for what counts
  lastReviewedAt?: IsoDateTime; // set by 'Reviewed — no change'
};
```

### 5.1 Derived, non-stored fields

These MUST be computed by `@flowmap/domain` projections and MUST NOT be persisted:

| Derived field               | Definition                                                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `sizeSummary: RelativeSize` | Band of `Σ countedFootprintUnits` against `sizeMapping`; `XL` when above the `L` value. Undefined when there are no footprints |
| `totalUnits`                | `Σ` units of all non-archived footprints                                                                                       |
| `isCarryOver`               | Any footprint has `carryOverFromQuarterId` set                                                                                 |
| `spanQuarters`              | Distinct quarters across non-archived footprints, ordered by ordinal                                                           |
| `hasOverflowContribution`   | Any footprint sits in a team-quarter with negative headroom                                                                    |

**R5:** there is no stored `Commitment.size`. Capacity comes only from footprint units.

### 5.2 Lifecycle transitions

```
                  ┌──────────────────── DropCommitment ─────────────────┐
                  │                                                     ▼
  (create)──► IDEA ──PassCommitGate──► COMMITTED ──StartDelivery──► IN_DELIVERY ──Complete──► DONE
                ▲                        │   ▲                        │   │
                └──RevertCommitGate──────┘   └────CorrectToCommitted───┘   │
                                             │                            │
                                        HoldCommitment              HoldCommitment
                                             ▼                            ▼
                                          ON_HOLD ◄────────────────────────┘
                                             │
                                       ResumeCommitment → priorActiveLifecycle
```

| From                         | To                     | Command              | Guard                                                           |
| ---------------------------- | ---------------------- | -------------------- | --------------------------------------------------------------- |
| `IDEA`                       | `COMMITTED`            | `PassCommitGate`     | Planner; Commit Gate guardrails (§03 §6)                        |
| `IDEA`                       | `DROPPED`              | `DropCommitment`     | Contributor                                                     |
| `COMMITTED`                  | `IDEA`                 | `RevertCommitGate`   | Planner; only while never `IN_DELIVERY`                         |
| `COMMITTED`                  | `IN_DELIVERY`          | `StartDelivery`      | Planner                                                         |
| `COMMITTED` \| `IN_DELIVERY` | `ON_HOLD`              | `HoldCommitment`     | Planner; records `priorActiveLifecycle`                         |
| `IN_DELIVERY`                | `COMMITTED`            | `CorrectToCommitted` | Planner; correction path only                                   |
| `IN_DELIVERY`                | `DONE`                 | `CompleteCommitment` | Planner                                                         |
| `ON_HOLD`                    | `priorActiveLifecycle` | `ResumeCommitment`   | Planner                                                         |
| any non-terminal             | `DROPPED`              | `DropCommitment`     | Planner (Contributor only from `IDEA`)                          |
| `DONE` \| `DROPPED`          | —                      | terminal             | Renewal creates a new commitment with `renewedFromCommitmentId` |

Any other transition is rejected with `ILLEGAL_LIFECYCLE_TRANSITION`. A commitment MUST NOT be
created directly in `IN_DELIVERY`; material unplanned work uses the streamlined
`CreateIdea → PassCommitGate → StartDelivery` path, which the UI offers as one action
("Capture unplanned work") that emits the three commands in one batch.

## 6. Capacity footprint

```ts
type CapacityFootprint = EntityEnvelope & {
  commitmentId: EntityId;
  teamId: EntityId;
  quarterId: QuarterId;
  units: CapacityUnits; // > 0. The single source of capacity truth.
  sizeAtCreation?: RelativeSize; // the band chosen when units were first resolved; display only
  unitsSource: 'SIZE_MAPPING' | 'EXPLICIT' | 'MIGRATED' | 'CARRY_OVER';
  confidence?: Confidence;
  isPrimary: boolean; // exactly one per commitment once committed
  carryOverFromQuarterId?: QuarterId;
  carryOverFromFootprintId?: EntityId;
  closedAsUnfinished?: boolean; // set at quarter close on the origin footprint
};
```

Invariants:

- `units > 0`. Removing load means removing the footprint, not setting it to zero.
- `(commitmentId, teamId, quarterId)` is unique among non-archived footprints. Increasing a team's
  load in a quarter edits the existing footprint.
- A commitment in `COMMITTED`/`IN_DELIVERY` MUST have exactly one footprint with `isPrimary: true`,
  and that footprint's `teamId` MUST equal `commitment.primaryTeamId`. Enforced at Commit Gate and
  on every footprint command.
- Footprints referencing a closed `TeamQuarter` are immutable.
- `sizeAtCreation` is display metadata. Changing the workspace size mapping never rewrites `units`
  (see [02](02-capacity-model.md#4-size-mapping-and-migration)).

Invariants:

## 8. Dependency and decision

```ts
type DependencyType =
  | 'REQUIRES' // default for visually created dependencies
  | 'BLOCKED_BY'
  | 'DEPENDS_ON_DELIVERY'
  | 'NEEDS_CAPACITY_FROM'
  | 'NEEDS_DECISION_APPROVAL_FROM';

type DependencyTarget =
  | { kind: 'COMMITMENT'; id: EntityId }
  | { kind: 'MILESTONE'; id: EntityId }
  | { kind: 'TEAM'; id: EntityId }
  | { kind: 'DECISION'; id: EntityId };

type Dependency = EntityEnvelope & {
  sourceCommitmentId: EntityId; // the work WAITING
  target: DependencyTarget; // the PREREQUISITE
  type: DependencyType; // default 'REQUIRES'
  ownerRef?: OwnerRef;
  neededBy?: IsoDate;
  status: 'OPEN' | 'AT_RISK' | 'RESOLVED'; // default 'OPEN'
  isHard: boolean; // true for BLOCKED_BY and NEEDS_DECISION_APPROVAL_FROM by default
  note?: string; // <= 280
};

type Decision = EntityEnvelope & {
  kind: 'DECISION' | 'APPROVAL';
  name: string; // 1..140
  ownerRef?: OwnerRef;
  neededBy?: IsoDate;
  status: 'OPEN' | 'AT_RISK' | 'RESOLVED';
  resolutionNote?: string; // <= 280
  resolvedAt?: IsoDateTime;
};
```

**Direction is invariant across all types (R6/decision 2026-08-14): `source` waits, `target`
unblocks.** The UI renders type labels so the sentence reads correctly in both directions
("Payments API _requires_ Security review" / "Security review _is required by_ Payments API") but
the stored direction never flips.

Invariants:

- A dependency MUST NOT be self-referential (`source === target` when target kind is `COMMITMENT`).
- `(sourceCommitmentId, target, type)` is unique among non-archived dependencies.
- **Cycles are permitted.** They represent reality. Cycle detection produces the `DEP_CYCLE`
  warning signal in Radar and a visual cycle badge in the Dependency Map; it never blocks entry.
- Archiving a target does not archive dependencies. Dependencies to archived targets produce the
  `DEP_TARGET_ARCHIVED` signal.

available today (see [08 §4.1](08-providers.md#41-identity-and-authorisation-without-an-identity-provider)).

External links open in the system browser via the Tauri shell opener. Enterprise systems are
referenced, never embedded — no webview, no iframe, no content fetch.

## 12. Referential integrity policy

| Action                   | Effect on referencing entities                                                                                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Archive `Team`           | Blocked if any non-archived footprint references it (`TEAM_HAS_ACTIVE_FOOTPRINTS`). Team-quarters archive with the team                                                                                          |
| Archive `ProductService` | Impacts referencing it are archived; commitments untouched; change-load excludes it                                                                                                                              |
| Archive `Commitment`     | Its footprints, impacts, milestones, links, and theme joins archive. Dependencies **survive** and raise `DEP_SOURCE_ARCHIVED` / `DEP_TARGET_ARCHIVED`                                                            |
| Archive `Decision`       | Dependencies targeting it survive and raise `DEP_TARGET_ARCHIVED`                                                                                                                                                |
| Archive `Person`         | Owner references survive and render as "archived person"; `OWN_ARCHIVED` signal raised where the item is committed                                                                                               |
| Archive `Theme`          | Joins archive                                                                                                                                                                                                    |
| Hard delete (Admin)      | Cascade-tombstones owned children (footprints, impacts, milestones, links, joins); referencing rows from other aggregates are **not** deleted, they keep a dangling ref rendered as "removed" and raise a signal |
| Restore                  | Restores the entity and its cascade-archived children, subject to current invariants (e.g. a restored footprint whose team-quarter is closed is restored archived)                                               |

Property test: **no non-archived entity may reference a hard-deleted entity without producing a
signal.** ([11 §3](11-quality-performance.md))

## 13. Schema versioning and migration

```ts
type WorkspaceSchema = {
  schemaVersion: number; // integer, monotonic; current: 1
  minReadableVersion: number; // oldest version this build can read
};
```

- Every workspace payload (local DB, portable package, provider store) carries `schemaVersion`.
- Migrations are **forward-only, monotonic, and idempotent**, registered as
  `{ from: n, to: n+1, up(workspace): workspace, describe(): string }` in `@flowmap/storage`.
- Before any migration the app writes a **local recovery backup** (`<workspaceId>.pre-migration-<n>.flowmap`)
  and offers a restore path if migration fails. Migration failure never leaves a half-migrated store:
  local migrations run inside a single SQLite transaction.
- A build refuses to open a workspace with `schemaVersion > build.schemaVersion` and says which
  version is needed.
- Round-trip tests cover at least `current` and `current − 1` ([11 §3](11-quality-performance.md)).
